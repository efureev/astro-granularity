# Granular Status — пример приложения

Панель состояния сервисов: три раздела на трёх языках, девятнадцать страниц.
Одновременно витрина интеграции и фикстура всех e2e-гейтов пакета.

## Запуск

Своих зависимостей у примера нет — он резолвит пакет через симлинк `link:..`,
а `astro`, `vue` и `unocss` находит в `node_modules` корня. Ставить что-либо
**внутри** `example/` нельзя: раскладка сломается, в дереве появится второй Vue.

```bash
# из корня репозитория
yarn install
yarn build                    # пример резолвит пакет из dist/, не из src/

cd example
npx astro build
node ../e2e/serve.mjs 4331 dist
```

`astro dev` в этом проекте не стартует (Astro 7.2.7 / Node 26), поэтому
проверять руками — только сборкой и статическим сервером.

**После любой правки `src/**` пакета нужен `yarn build` в корне.** Иначе пример
соберётся с прошлой версией интеграции, и никакой ошибки при этом не будет.

## Что он показывает

| | |
| --- | --- |
| Тема без мигания | инлайн-скрипт интеграции + свой `ThemeToggle.astro`, вложенный слотом в остров шапки |
| Строки в HTML | переводы ядра приезжают разметкой, а не догрузкой — `i18n.ssrStrings` |
| Три языка | `en` без префикса, `/ru/`, `/es/`; маршруты через `[lang]` + `getStaticPaths` |
| Серверные и клиентские острова | на каждой странице по одному того и другого |
| Пять базовых компонентов | `GrButton`, `GrCard`, `GrDialog`, `GrTooltip`, `GrSelect` |
| Авто-импорт | резолвер интеграции — в `.vue`; в `.astro` импорты явные |
| Контент-коллекции | отчёты об инцидентах на Markdown, по файлу на язык; типографика на токенах |
| Клиентская навигация | `ClientRouter`: тема и язык строк переживают подмену документа |
| Второй пакет строк | `@feugene/granularity-chrono`: `deriveI18nBlocks` выводит оба блока сам |
| Валидация формы | `GrForm` + `GrFormField`: правила по имени поля, тексты ошибок — из строк ядра |
| Изображения | `astro:assets`: WebP, три ширины, размеры в разметке, обязательный `alt` |
| Страницы ошибок | 404, 401, 403, 500 на общем компоненте, `noindex`, выход наружу |

### Острова

| Остров | Страница | Режим | Почему |
| --- | --- | --- | --- |
| `SiteHeader` | обе | `client:load` | навигация обязана быть в разметке |
| `SiteFooter` | обе | `client:load` | тултип версии и возврат наверх |
| `ServiceBoard` | `/` | `client:load` | список сервисов — содержимое страницы |
| `LastChecked` | `/` | `client:only` | «N минут назад» от момента просмотра — сервер этого момента не знает |
| `PreferencesForm` | `/settings/` | `client:load` | форма с умолчаниями видна без JS |
| `SavedPreferences` | `/settings/` | `client:only` | читает `localStorage` этого браузера |

`server:defer` здесь недоступен: Astro требует под него адаптера, а адаптер
отменил бы статическую сборку. Поэтому «серверный остров» — это отрисованный
на сервере и гидратированный.

## Lighthouse

**100 по доступности, лучшим практикам и SEO на всех страницах.
Производительность — 99–100.**

| Тип страницы | Perf | A11y | Best | SEO |
| --- | --- | --- | --- | --- |
| Обзор (`/`, `/ru/`, `/es/`) | 99–100 | 100 | 100 | 100 |
| Инциденты, список | 99–100 | 100 | 100 | 100 |
| Инцидент с графиком | 100 | 100 | 100 | 100 |
| Настройки с формой | 99–100 | 100 | 100 | 100 |

Показатели: LCP 0.7–0.8 с, CLS **0**, TBT **0 мс**.

Про 99 честно: балл теряется округлением, а не дефектом — FCP 0.6 с даёт 0.99,
LCP 0.8 с даёт 0.98. Главная статья расхода — **68 КБ блокирующего CSS**, из
которых на конкретной странице не нужно около 47 КБ. Это свойство единого листа
UnoCSS на весь сайт: он содержит стили всех подключённых компонентов, а страница
использует часть. Разложить его по страницам без потери общего кэша нельзя.

### Условия замера

Lighthouse 13.4.1, `--preset=desktop`, headless Chrome, по **собранному** `dist`
через `e2e/serve.mjs` на `localhost`. Воспроизвести:

```bash
cd example && npx astro build
node ../e2e/serve.mjs 4331 dist &

CHROME_PATH="…/Google Chrome for Testing" \
npx lighthouse http://localhost:4331/ --preset=desktop \
  --chrome-flags="--headless=new"
```

Замер на локальной статике — не то же самое, что на настоящем хостинге: нет
сетевой задержки, TLS и CDN. Он честно измеряет то, за что отвечает приложение
(разметку, вес, сдвиги макета), и ничего не говорит про доставку.

### Чем достигнуто

- **Ни одного веб-шрифта.** Системный стек `--gr-font-ui`, иконки интерфейса —
  инлайновый SVG. Нечего ждать и нечего сдвигать.
- **Картинки через `astro:assets`.** WebP, три ширины в `srcset`, размеры в
  разметке — место зарезервировано до загрузки, CLS остаётся нулевым. `alt`
  обязателен: без него Astro роняет сборку.
- **CSS сужен списком компонентов.** `components` в `uno.config.ts` — явное
  перечисление, а не `'all'`: пресет дотягивает транзитивные зависимости сам,
  а `'all'` эмитит стили всех 78 компонентов ядра.
- **Место под `client:only`-острова зарезервировано** в разметке страницы, а не
  внутри компонента: до монтирования компонента не существует.
- **Строки приезжают разметкой.** Иначе переводы меняли бы текст после
  гидратации — сдвиг ровно там, где стоит основной контент.
- `<meta viewport>`, `description`, canonical, `hreflang` на три локали и
  `x-default`, Open Graph с абсолютной обложкой, `robots.txt`, карта сайта
  эндпоинтом на 18 адресов; `<h1>` на каждой странице, landmarks, skip-link,
  `scroll-padding-top` под липкую шапку, локализованные доступные имена.
- Страница 404 отдаёт `noindex, follow` и не помечает текущим ни один пункт меню.

## Страницы ошибок

Четыре кода на общем компоненте `ErrorPage.astro`: точка тона, крупный
моноширинный код, линия сигнала (на `500` она обрывается), объяснение и выход.

**Автоматически работает только 404.** Astro считает особыми ровно два маршрута
— `/404` и `/500` (`STATUS_CODE_PAGES`), и пишет их плоскими файлами
`404.html` и `500.html`; хостинг подставляет `404.html` сам. Остальное:

| Код | Файл | Кто отдаёт |
| --- | --- | --- |
| 404 | `dist/404.html` | хостинг, на любой неизвестный путь |
| 500 | `dist/500.html` | адаптер SSR при ошибке; на статике — обработчик хостинга |
| 401 | `dist/401/index.html` | только настроенный хостинг или edge |
| 403 | `dist/403/index.html` | то же |

То есть 401 и 403 — готовая разметка, на которую хостинг надо **направить**.
Сами по себе они не сработают, и притворяться иначе тут нечем.

**Lighthouse даёт им SEO 63 — и это правильно.** Единственный провал —
`is-crawlable`: страница закрыта `noindex, follow`. Индексировать страницу
ошибки не надо, поэтому низкий SEO здесь означает верную настройку, а не дефект.
Снимать `noindex` ради балла нельзя.

## Грабли

Самое дорогое из найденного на этом примере:

- **Утилиты, использованные только внутри `client:only`-острова, в CSS не
  попадают** — если не добавить свои исходники в `content.filesystem`. Остров
  приезжает без стилей, молча. Строка в `uno.config.ts` это и лечит.
- **Панель `GrSelect` после гидратации уезжает телепортом в `body`** — тест с
  включённым JS не найдёт её содержимое внутри разметки компонента.
- **`ClientRouter` сбрасывает всё, что живёт вне разметки** — атрибуты `<html>`
  снимаются подменой, модули не переисполняются. Проверять только настоящей
  ссылкой: `location.href` идёт в обход роутера, и дефекты не воспроизводятся.
- **Растровый график не следует теме** — PNG не знает про `data-theme`. Оставлено
  осознанно: пример показывает `astro:assets`, а не борьбу с ним.
