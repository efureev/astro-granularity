# Диагностика

[English](./troubleshooting.md) · **Русский**

Симптомы в том порядке, в каком вы их скорее всего встретите.

## «Правка в пакете не видна»

Самая частая и самая тихая. Приложение резолвит пакет через его `exports`, а те ведут в
`dist/`. Правка исходника без пересборки не меняет ничего, и никакой ошибки об этом не скажет.

```bash
yarn build   # затем пересобрать сайт
```

## «Компонент приехал голым»

Четыре проверки, в этом порядке:

1. `granum(granumConfig)` есть в `vite.plugins`. Без него не эмитится ничего вовсе — и
   интеграция об этом говорит, роняя сборку.
2. `import 'virtual:granum.css'` есть в лейауте. Плагин порождает таблицу стилей;
   импортировать её — дело приложения.
3. Компонент есть в селекции `components` — `granum explain <config> '<pkg>:<Name>'`
   отвечает, почему он в сборке или почему его там нет. Транзитивные зависимости
   замыкаются сами, поэтому `GrDialog` приводит `GrModal`.
4. За классом стоит правило — `granum why-css <config> '<class>'`.

## «Кнопка цветная, но текст наследует цвет страницы — или пропали отступы»

Сброс браузерных стилей оказался вне каскадного слоя. Нелейерный CSS бьёт *любой*
`@layer` независимо от специфичности, поэтому `button { color: inherit; padding: 0 }` из
сброса перебивает утилиты компонента, живущие в `@layer granum.utilities`.

```css
/* src/styles/reset.css */
@import '@unocss/reset/tailwind-compat.css' layer(reset);
```

Слой обязан объявиться **до** слоёв granum — место слоя в каскаде задаёт его первое
появление, — поэтому этот файл идёт первым импортом лейаута.

## «Сборка падает с `ComponentOutsideSelectionError`»

Импортируется компонент, которого нет в селекции `components`. Либо добавьте его, либо
переключитесь на `components: 'imports'` — тогда селекция пойдёт за импортами.

Guard видит только импорты, пережившие транспиляцию: неиспользуемый импорт вырезается
до того, как бандлер его разрешит, — поэтому неиспользуемый компонент не роняет сборку и
не даёт CSS.

## «Оверлей пустой»

`client:only` это вызывает, а не лечит: он выбрасывает серверную разметку. Оверлеям нужен
`client:load`. См. [Острова](./islands.ru.md#оверлеям-clientonly-не-нужен).

Если оверлей пуст именно **на сервере** — возможно, это верно: `GrModal` не отдаёт свой слот на сервер даже открытым.

## «Строки компонентов пустые или показывают сам ключ»

- В `vue()` не указан `appEntrypoint: '@feugene/astro-granularity/app'` — экземпляр i18n не создаётся вовсе.
- Ключ показывает сам себя вместо английского текста — не отработал `preloadFallback`:
  без него `fallbackLocale` объявлен, но пуст до первого переключения языка.

## «Строки в HTML английские, а после гидратации становятся русскими»

Снимок не доехал. По порядку:

1. `i18n.ssrStrings: false` — выключено явно.
2. Нет блока `i18n` в `astro.config.mjs` **и** пуст `i18n.locales` —
   `Astro.currentLocale` равен `undefined`, сопоставлять сегмент пути не с чем, и язык всегда `defaultLocale`.
3. Строки читаются через `tm()` — таких в `'used'` нет по устройству, они доезжают фоновой догрузкой.

Смотреть глазами: `<script type="application/json" data-granularity-i18n>` в собранной странице. Нет блока — снимок не
снялся; есть, но с чужой локалью — маршрут разобрался не так, как вы ожидаете.

## «Снимок раздулся»

`ssrStrings: 'full'` кладёт весь словарь языка страницы в **каждую** страницу — на примере это 8.6 КБ JSON против 303 Б
у `'used'`. Заодно помечает блок загруженным, и словарь перестаёт быть общим кэшируемым чанком. Для многостраничного
сайта проигрыш дважды.

## «Страница мигает: скрипта режима нет»

В `<head>` собранной страницы нет инлайн-скрипта с парами. Почему — скажет лог сборки:

1. **Предупреждение `theme-script-skipped`.** Плагин granum добавила другая интеграция, идущая после
   `astro-granularity`: на настройке этой интеграции плагина в `vite.plugins` ещё не было, и строить скрипт было не из
   чего. CSS при этом приезжает — поэтому случай и легко проглядеть. Поставьте `granum(granumConfig)` прямо в
   `vite.plugins` конфига Astro.
2. **Ошибка `granum-without-theme-manifest`.** Установленный granum не отдаёт манифест режимов до сборки. Поднимите
   `@feugene/granum` и `@feugene/granum-engine-wind` до `^3.2.0`. При `strict: false` сборка идёт дальше без скрипта —
   и страница мигает.

В логе ни того, ни другого? Значит, задан `injectThemeScript: false` или в сборке granum нет режимов вовсе.

## «Компоненты светлые в тёмном режиме — `data-theme="dark"` ничего не делает»

Ядро 2 оформляется только парой: `[data-theme="slate-dark"]`. Голое имя режима — `data-theme="dark"`, как ставили
интеграция 1.x и написанные под неё переключатели, — не совпадает ни с одним селектором: компоненты остаются в режиме
по умолчанию, а с ними и `color-scheme`. Ваш CSS на `[data-theme='dark']` замолкает точно так же.

Берите пары из сборки, а не пишите их: переключайте режим контроллером granum —
`createThemeController(manifest, { storageKey: 'gr-theme' })` поверх `import manifest from 'virtual:granum/themes'` —
или `useTheme()` ядра. См. [Тему](./theme.ru.md#свой-переключатель). В своём CSS выбирайте по паре, а лучше берите
цвета из токенов `--gr-*` — тогда селектор не нужен вовсе.

## «Выбранный режим не переживает перезагрузку»

- **Другой ключ.** Контроллер granum, если не сказать иначе, пишет под `granum-theme`, а скрипт читает
  `themeStorageKey` — по умолчанию `gr-theme`. Передайте `storageKey: 'gr-theme'`.
- **Сохранена пара вместо имени.** В `localStorage['gr-theme']` лежит `dark`, а не `slate-dark`; всё, что не режим
  сборки, пропускается.
- **`data-theme` вписан в лейаут.** Пару, уже стоящую на `<html>`, скрипт принимает за серверную и оставляет, поэтому
  сохранённый выбор не применяется никогда. Уберите атрибут из разметки; на сервере ставьте его только по cookie — см.
  [рецепт 6](./recipes.ru.md#6-серверный-рендеринг).
- **Приватный режим Safari.** Запись в хранилище там бросает. Режим всё равно переключится, просто не сохранится.
  Контроллер granum это ловит; переключателю, который пишет в хранилище руками, нужен свой `try/catch`.

## «Режим сбрасывается после клиентского перехода»

`ClientRouter` снимает с `<html>` все атрибуты и копирует их из полученного документа, а в нём `data-theme` нет, если
пару не вписал сервер. Скрипт интеграции заново применяет сохранённый режим на `astro:after-swap`, поэтому режим,
потерянный на переходе, был сохранён не там, где его читает скрипт, — см. предыдущий раздел. При
`injectThemeScript: false` повтор — забота вашего раннего скрипта: см. [Тему](./theme.ru.md#клиентская-навигация).

## Сборка падает: `Received protocol 'virtual:'`

`@astrojs/vue` ломает статическую сборку на любом `.vue`-острове: его `dist/server.js`
импортирует `virtual:astro:vue-app`, а входная точка пререндера тянет его голым спецификатором.

Интеграция обходит это сама, заставляя Vite встроить пакет в бандл пререндера. Действий не требуется — но если
переопределяете `vite.environments.prerender` или `vite.environments.ssr`, сохраните `noExternal`.

## Сборка или dev-сервер падают: `ERR_UNKNOWN_FILE_EXTENSION: ".css"`

Собранные чанки дизайн-системы `.css` не импортируют — собственный лист компонента приезжает на страницу через granum, —
поэтому Node грузит пакеты как есть, и в `prerender`, и в `ssr`. Такая ошибка значит, что в проекте спутник, собранный
раньше 1.0.1, когда сборка ещё вшивала `import './styles.css'` в чанк. Обновите его до 2.x — линии, которая идёт с
ядром 2.

## Сборка падает: `ComponentRootImportError`

Компонент импортирован из корня пакета: `import { GrButton } from '@feugene/granularity'`. granum это отвергает: его
селекция видит компонент только по подпути, а корень тянет весь пакет. Импортируйте из подпути,
`@feugene/granularity/components/GrButton`; в `.vue` его за вас пишет резолвер авто-импорта. Утилиты, плагины и типы из
корня брать можно.

## Строка сборки granum насчитала классы «без правила»

granum называет класс из вашей разметки, которого нет ни у движка, ни в CSS сборки: опечатку или класс, чьё правило
удалили. Отчёт читает CSS всех окружений сборки, а `.css`-файл из `appSources` объявляет свои классы, даже если едет на
страницу строкой (`?raw` в `<style set:html>`), поэтому у класса из списка правила нет нигде. Объяснит конкретный —
`granum why-css <config> '<class>'`, а `granum report --strict` можно ставить в CI.

## Сборка падает: `Rolldown failed to resolve import "@floating-ui/dom"`

Не-опциональный peer ядра. Поставьте его:

```bash
yarn add -D @floating-ui/dom
```

## Сборка падает: `"createFintI18n" is not exported by "__vite-optional-peer-dep:@feugene/fint-i18n/core…"`

Задан `appEntrypoint: '@feugene/astro-granularity/app'`, а `@feugene/fint-i18n` не установлен. Это опциональный peer:
ни один менеджер пакетов его не добавит, и Vite подменяет недостающий модуль пустой заглушкой. Поставьте его:

```bash
yarn add @feugene/fint-i18n
```

Со своим i18n-рантаймом направьте вместо этого `appEntrypoint` на свою обвязку — см.
[рецепт 3](./recipes.ru.md#3-свой-i18n-рантайм).

## Сборка предупреждает о бюджете скрипта режима

512 байт на теме из двух режимов: для самого пакета это гейт, для вашей сборки — предупреждение. Скрипт блокирует первую
отрисовку, и каждый режим вашей сборки добавляет в него своё имя и пару: на `slate` из двух режимов это 407 байт, с
`themeCookie` — 497. Сверх бюджета ничего не ломается: предупреждение называет размер и число режимов, а стоит ли каждый
режим своих байт на критическом пути — решать вам.

## `@feugene/astro-granularity/client` не резолвится

Починено в релизе после `0.3.0`. До него подпуть отсутствовал в `exports`, хотя
`client.d.ts` уезжал в тарбол, — и ссылка не разрешалась при `moduleResolution: bundler`
и `node16`: `exports` закрывает всё, чего в нём не перечислено. Обновитесь либо ссылайтесь на файл путём.

## `astro dev` не стартует

Известное, причина не установлена: `Dev server process exited before becoming ready` на Astro 7.2.x и Node 26. Проверять
руками — сборкой и статическим сервером.

Одно следствие стоит назвать: Vue сообщает о расхождениях гидратации только в dev-сборке, поэтому пока `astro dev`
недоступен, их не показывает ничто.
