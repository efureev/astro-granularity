# Справочник

[English](./reference.md) · **Русский**

Все опции, экспорты и диапазоны — вместе с причинами, по которым дефолты именно такие.

## Опции

```ts
granularity({ /* … */})
```

| Опция               | По умолчанию | Что делает                                                                                |
|---------------------|--------------|-------------------------------------------------------------------------------------------|
| `themeStorageKey`   | `'gr-theme'` | Ключ `localStorage` с именем режима. Обязан совпадать с `useTheme` ядра (`GR_THEME_STORAGE_KEY`) |
| `themeCookie`       | —            | Cookie с именем режима — для SSR с `createCookieStorage` granum. Скрипт читает её раньше `localStorage` |
| `injectThemeScript` | `true`       | Вставлять инлайн-скрипт режима в `<head>`. Пары для него — от плагина granum в `vite.plugins` |
| `resolver`          | `true`       | Регистрировать резолвер авто-импорта: `GranularityResolver()` из `@feugene/unplugin-granularity` от корня проекта — для ядра и всех спутников из его `package.json` |
| `i18n`              | `{}`         | Строки: `{ packages, locales, ssrStrings }`. `false` — не порождать модуль лоадеров вовсе |
| `i18n.packages`     | `[]`         | Спутники помимо ядра. Ядро подключается всегда                                            |
| `i18n.locales`      | `[]`         | Языки приложения. Пусто — берётся агрегат `/i18n/all` со всеми, что есть в пакете         |
| `i18n.ssrStrings`   | `'used'`     | Снимок в HTML: `'used'`, `'full'` или `false`. Работает при любом режиме вывода — состояние страницы контекстное (`AsyncLocalStorage`) |
| `strict`            | `true`       | Ронять сборку на проблемах окружения, а не ограничиваться предупреждением                 |

Опции проверяются в `resolveOptions` и бросают `TypeError` с префиксом
`[astro-granularity]`. Проверка на границе, а не по месту использования: опечатка всплывает при конфигурировании, а не в
середине сборки.

Режим по умолчанию — не опция интеграции: он принадлежит теме в `granum.config`, а без сохранённого выбора скрипт
следует системной схеме. См. [Тему](./theme.ru.md).

### Откуда берётся CSS

Интеграция не эмитит CSS вовсе. Он приезжает из `@feugene/granum` — обычного плагина
Vite, который регистрируете вы сами:

```js
vite: {plugins: [granum(granumConfig)]}
```

и вывод которого вы сами же импортируете, в одном месте — в лейауте:

```astro
---
import '../styles/reset.css'   // @import '@unocss/reset/tailwind-compat.css' layer(reset);
import 'virtual:granum.css'    // пять каскадных слоёв granum.*
import '../styles/theme.css'   // своё, вне слоёв — и потому побеждает
---
```

**Порядок несущий, и из кода он не виден.** `virtual:granum.css` несёт пять каскадных
слоёв `granum.{tokens,base,themes,components,utilities}`, а место слоя в каскаде задаёт
его первое появление. Нелейерный CSS бьёт *любой* `@layer` независимо от специфичности,
поэтому:

- сброс браузерных стилей обязан лежать в слое, объявленном до слоёв granum, иначе
  `button { color: inherit; padding: 0 }` из него перебьёт утилиты компонентов;
- своё оформление страницы выигрывает у дизайн-системы именно потому, что слоя не
  объявляет, — и это замысел, а не случайность.

Обе поломки тихие: ни ошибки, ни предупреждения, просто компонент выглядит не так.

Проекту, которому нужна шкала `--gr-*` и режимы для своей разметки, а компонентами он не
пользуется вовсе, для CSS не нужны ни плагин, ни виртуальный модуль: хватит одной строки
`import '@feugene/granularity/styles.css'`. А вот скрипт режима строится из манифеста
плагина, поэтому без плагина его нет, и поставить пару до первой отрисовки (`slate-light`
или `slate-dark` для этой таблицы стилей) придётся самим. Проверка окружения плагин всё
равно потребует — выключите её через `strict: false`.

### Зачем нужен `i18n.locales`

Явный список переключает порождаемый модуль на **именованные** импорты локалей, и неиспользуемые языки отсекаются
сборкой. Оставите пустым — приедет агрегат `/i18n/all`
со всеми языками пакета; у ядра это `en`, `ru` и `es`.

Имена блоков перечислять не нужно никогда: они лежат внутри самих коллекций лоадеров, и
`deriveI18nBlocks` читает их оттуда.

## Подпути

| Подпуть          | Что отдаёт                                                        |
|------------------|-------------------------------------------------------------------|
| `.`              | Дефолтный экспорт — фабрика интеграции. Именованные экспорты ниже |
| `./app`          | `setup` для `vue({ appEntrypoint: … })` и `getGranularityI18n()`  |
| `./runtime`      | Браузерные кирпичи и шов снимка строк                             |
| `./middleware`   | `onRequest`. Регистрирует интеграция; импортировать не нужно      |
| `./client`       | Только типы: `declare module 'virtual:granularity/i18n'`          |
| `./package.json` | Сам манифест                                                      |

`./client` — ambient-объявление для приложений со своей точкой входа:

```ts
/// <reference types="@feugene/astro-granularity/client" />
```

В записи объявлено только условие `types` — модуля за ней нет, поэтому импорт подпути в рантайме падает намеренно. Он
существует для компилятора, а не для сборщика.

## Именованные экспорты корня

Сборочные хелперы, вынесенные наружу потому, что их можно проверить в изоляции:

- `createThemeScript(manifest, { storageKey, cookie? })` — код скрипта режима по манифесту granum
  в том виде, в каком он уходит в `injectScript('head-inline', …)`; `THEME_SCRIPT_BUDGET_BYTES` — его бюджет, 512
- `buildI18nModuleSource`, `assertPackageSpecifier`, `VIRTUAL_I18N_ID`
- `createVirtualI18nPlugin` и его типы
- `createVirtualThemePlugin`, `buildThemeModuleSource`, `VIRTUAL_THEME_ID` — модуль `virtual:granularity/theme` (`storageKey`, `cookie`) для своей точки входа
- `GRANUM_PLUGIN_NAME`, `VUE_INTEGRATION_NAME`
- Типы: `GranularityAstroOptions`, `ResolvedOptions`, `SSRStringsMode`, `ThemeScriptOptions`

Плюс реэкспорт поверхности `./runtime` для удобства.

**Шов снимка из корня намеренно не экспортируется.** `dist/index.js` исполняется в процессе конфига Astro, а `app.js` и
`middleware.js` — в бандле пререндера. Реестры модулей у них разные, поэтому `readServerPageLocale()`, взятый из корня,
всегда читал бы пустоту. Берите из `./runtime`, где он работает.

## Именованные экспорты `./runtime`

Ничто здесь не импортирует `@feugene/fint-i18n`, даже в типах: приложение вправе взять другой i18n-рантайм, поэтому
формы описаны структурно.

| Экспорт                                          | Назначение                                                                                                |
|--------------------------------------------------|-----------------------------------------------------------------------------------------------------------|
| `provideGranularityI18n(app, adapter, options?)` | Отдать адаптер ядру. Нужны только `t` и, если умеет, `te`                                                 |
| `deriveI18nBlocks(loaders)`                      | Имена блоков, прочитанные из коллекций лоадеров                                                           |
| `readPageLocale(defaultLocale)`                  | Язык страницы из `<html lang>`                                                                            |
| `readServerPageLocale()`                         | Язык маршрута, объявленный middleware на сборке                                                           |
| `readSnapshotFromDocument()`                     | Снимок строк из разметки                                                                                  |
| `registerSnapshotBuilder(fn)`                    | Зарегистрировать того, кто снимок строит                                                                  |
| `SNAPSHOT_ATTR`                                  | `data-granularity-i18n`                                                                                   |
| Типы                                             | `GranularityLocaleLoaders`, `GranularityI18nAdapterLike`, `ProvideI18nOptions`, `GranularityI18nSnapshot` |

## Виртуальный модуль

`virtual:granularity/i18n` порождается на этапе конфига из ваших опций:

```ts
export const loaders: GranularityLocaleLoaders[]  // уплощённые коллекции лоадеров
export const blocks: string[]                     // выведены из `loaders`
export const defaultLocale: string                // из `i18n.defaultLocale` Astro
export const locales: string[]                    // из `i18n.locales`
export const ssrStrings: 'used' | 'full' | false  // из `i18n.ssrStrings`
```

Его исходник собирается подстановкой в строку, поэтому каждое приходящее значение сперва проверяется —
`assertLocaleName` и `assertPackageSpecifier` — и эмитится через
`JSON.stringify`. Два независимых слоя: значение конфига, ставшее исполняемым кодом в чужой сборке, — не теоретическая
проблема.

## Проверка окружения

Шесть кодов, отчёт о них управляется `strict`: на ошибке `true` роняет сборку, `false`
пишет в лог и продолжает; предупреждение сборку не роняет никогда.

| Код | Уровень | Когда |
| --- | --- | --- |
| `no-vue-integration` | error | среди интеграций нет `@astrojs/vue`: Astro нечем рендерить `.vue` |
| `no-granum-plugin` | error | в `vite.plugins` нет `granum:app`: ни утилит, ни токенов, ни тем — компоненты отрисуются голыми |
| `duplicate-granum-plugin` | error | два инстанса держат две резолюции и пишут два отчёта, а виртуальные модули отдаёт тот, что успел первым |
| `granum-without-theme-manifest` | error | плагин granum не отдаёт манифест режимов до сборки (`api.themeManifest`): granum ниже 3.2, которого требует диапазон. Без пар нет скрипта режима, и первый кадр мигнёт |
| `granum-plugins-unreadable` | warn | список плагинов развернуть не удалось. «Не проверили» — не то же, что «нет» |
| `theme-script-skipped` | warn | на настройке этой интеграции плагина granum в `vite.plugins` ещё не было — его добавила другая интеграция позже. CSS приедет, скрипт режима — нет |

Оба кода режима, `granum-without-theme-manifest` и `theme-script-skipped`, возможны только
при включённом `injectThemeScript`.

**Живёт в `astro:config:done`, а не в `astro:config:setup`.** Список плагинов полон
только после того, как отработали все интеграции, поэтому проверка в `setup` роняла бы
исправный проект в зависимости от порядка интеграций. Побочная польза: `@astrojs/vue`,
добавленный другой интеграцией, тоже виден.

Исключение одно — скрипт режима: вставить его можно только в `setup`, поэтому манифест
ищется там. А что нашлось, оценивается в `done`, по полному списку, — так плагин,
добавленный позже, отличается от отсутствующего.

## Peer-диапазоны

| Peer                   | Диапазон          | Опциональный |
|------------------------|-------------------|--------------|
| `astro`                | `>=7.0.0 <8.0.0`  | нет          |
| `@astrojs/vue`         | `>=7.0.0 <8.0.0`  | да           |
| `@feugene/granularity` | `>=2.0.0 <3.0.0`  | нет          |
| `@feugene/granum`      | `>=3.2.0 <4.0.0`  | нет          |
| `@feugene/fint-i18n`   | `>=0.9.0 <1.0.0`  | да           |

`@feugene/granum` обязателен: интеграция читает `api.themeManifest` плагина, а скрипт режима
ей пишет `createThemeScriptCode` из `@feugene/granum/runtime`. Нижняя граница — 3.2: `api`
манифеста появился в 3.1, а `reapplyOn` генератора, повторяющий режим после подмены
`ClientRouter`, — только в 3.2.

**Нижняя граница равна версии, на которой гоняется гейт.** Диапазон, заявляющий поддержку того, что никто не проверял,
хуже узкого: установка проходит, а поломка всплывает позже, у вас в приложении. Расширение диапазона означает, что
комбинация действительно прогонялась, а не что она «должна работать».

Промежуточные мажоры Astro не поддерживаются решением, а не по недосмотру: интеграция опирается на
`vite.environments.prerender`, которого до Astro 6 не было, и проверяется только на 7.

`@astrojs/vue` опционален, потому что сайту, которому нужен лишь режим без мигания, Vue-острова не нужны вовсе.
`@feugene/fint-i18n` опционален, потому что приложение может принести свой i18n-рантайм —
см. [рецепт 3](./recipes.ru.md#3-свой-i18n-рантайм). На нём построен единственный вход — `./app`: с
`appEntrypoint: '@feugene/astro-granularity/app'` его нужно поставить, а опциональный peer сам не ставит никто.

## Что не публикуется

В `files` — `dist` и `client.d.ts`. Исходники, пример и эти документы остаются в репозитории. Новый публикуемый каталог
обязан быть добавлен **и** в `files`, **и** в
`exports`: пропуск любого из двух даёт пакет, который ставится, но не импортируется.
