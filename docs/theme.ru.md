# Тема

[English](./theme.md) · **Русский**

## Зачем вообще инлайн-скрипт

Тема выбирается на сборке, режим — в рантайме. Ядро переключает режимы одним атрибутом на `<html>` — **парой** темы
сборки и режима, `data-theme="slate-dark"`. На статической сборке HTML одинаков для всех посетителей, поэтому пару
может поставить только код в браузере — и поставить он обязан **до первой отрисовки**. Всё отложенное, собранное в
бандл или живущее на уровне модуля опаздывает: страница отрисуется светлой и перекрасится на глазах у читателя.

Интеграция вставляет синхронный инлайн-`<script>` в `<head>`. Около 400 байт, без `src`, без `defer`, без `async`. Все
три свойства несущие, и все три держит гейт, снимающий настоящие кадры отрисовки через CDP: скриншот после `load`
показал бы установившийся режим и мигание пропустил.

Код пишет сам granum (`createThemeScriptCode` из `@feugene/granum/runtime`), поэтому режим он выбирает по тому же
правилу, что и контроллер granum, на котором стоит `useTheme` ядра, — скрипт и рантайм разойтись не могут:

1. пара, уже стоящая на `<html>`, остаётся — её поставил сервер;
2. иначе cookie, если задана `themeCookie`;
3. иначе имя режима в `localStorage`;
4. иначе системная схема: первый режим, чей `colorScheme` совпал с `prefers-color-scheme`;
5. иначе режим темы по умолчанию.

Код собирается под вашу сборку: пары и выбор по системной схеме вшиты константами, а ветка cookie есть только при
`themeCookie`. То, что нужно сверху Astro, — повтор после клиентского перехода, — тоже опция granum, `reapplyOn`;
интеграция лишь называет событие, `astro:after-swap`.

## Откуда берутся пары

Из сборки granum, а не из ваших рук. Режимы, их пары и атрибут решает `granum.config`: `theme: 'slate'` с
`modes: { names: ['light', 'dark'] }` дают `slate-light` и `slate-dark`. Интеграция спрашивает их у плагина granum в
`vite.plugins` (`api.themeManifest`) на этапе `astro:config:setup`. Это тот же конфиг, из которого собирается CSS,
поэтому скрипт не может поставить пару, которой в таблице стилей нет.

У такого порядка два следствия:

- **`granum(granumConfig)` обязан стоять прямо в `vite.plugins` конфига Astro.** Плагина, которого добавит другая
  интеграция позже, к моменту сборки скрипта ещё нет: CSS приедет, скрипт — нет, и сборка предупредит
  `theme-script-skipped`.
- **granum нужен 3.2 или новее.** Плагин, который не отдаёт манифест до сборки — без `api.themeManifest`, — роняет
  сборку ошибкой `granum-without-theme-manifest` (при `strict: false` она только пишется в лог), потому что без пар
  первый кадр мигнёт.

Сборка без режимов не получает скрипта вовсе: ставить нечего.

## Контракт из двух точек

Тот, кто режим **пишет**, обязан совпасть со скриптом, который его **читает**:

```js
localStorage.getItem('gr-theme')                     // 'dark' — имя режима; ключ = опция `themeStorageKey`
document.documentElement.getAttribute('data-theme')  // 'slate-dark' — пара из манифеста сборки
```

Хранится имя, а не пара, поэтому выбор переживает смену темы на сборке. `color-scheme` в контракт больше не входит: его
объявляет CSS режима — `[data-theme="slate-dark"] { color-scheme: dark }`, — потому что инлайн-стиль пережил бы режим,
переключённый в рантайме через `useTheme`, а тот пишет только атрибут.

Пишите обе точки контроллером granum — и контракт соблюдается сам собой, см. ниже. Промах руками будет молчаливым:

| Промах | Что произойдёт |
| --- | --- |
| Ключ — например, собственный дефолт granum `granum-theme` | Выбор не переживёт перезагрузку: под `gr-theme` скрипт не найдёт ничего и пойдёт за системной схемой |
| Сохранена пара вместо имени | То же самое: `slate-dark` — не режим, и скрипт его пропустит |
| Имя режима на `<html>` — `data-theme="dark"` | Не совпадёт ни с одним селектором: компоненты останутся в режиме по умолчанию, а с ними и `color-scheme` |
| Пара, набранная руками | Работает, пока не сменится тема в `granum.config`, а потом молча не совпадает ни с чем |
| `data-theme`, вписанный в лейаут | Скрипт примет его за пару от сервера и оставит: ни сохранённый выбор, ни системная схема не применятся никогда |

Своему CSS тоже незачем зависеть от имени темы. По порядку: цветам из ролей `--gr-*` селектор не нужен вовсе; утилиты
`dark:` в разметке следуют за всеми режимами сборки с тёмной схемой; `light-dark(светлое, тёмное)` выбирает цвет по
`color-scheme` режима; для того, что не цвет, — суффикс пары `[data-theme$='-dark']`, и никогда `[data-theme='dark']`.
Полный порядок и ловушка вложенных островов — в
[`modes.md`](https://github.com/efureev/granularity/blob/main/packages/granularity/docs/modes.md#свой-css-под-режим)
ядра; по нему написан `styles/theme.css` примера.

## Свой переключатель

Пакет публикует только читающую половину. Переключатель режима — разметка приложения, и Vue ради одной кнопки поднимать
незачем: `<button>`, один делегированный слушатель и контроллер granum поверх манифеста сборки — вся реализация.

```astro
---
interface Props { class?: string }
const { class: className } = Astro.props
---

<button type="button" class={className} data-theme-toggle>
  <slot />
</button>

<script>
  import { createCookieStorage, createThemeController } from '@feugene/granum/runtime'
  import manifest from 'virtual:granum/themes'
  import { cookie, storageKey } from 'virtual:granularity/theme'

  function toggle() {
    // Контроллер на каждое нажатие, а не один на модуль: `ClientRouter` подменяет
    // документ, не переисполняя модуль, а свежий контроллер узнаёт режим по паре.
    // Ключ и cookie — из интеграции, те же, что читает скрипт.
    const themes = createThemeController(manifest, cookie
      ? { storage: createCookieStorage({ name: cookie }) }
      : { storageKey })
    const scheme = themes.modes().find(mode => mode.name === themes.mode)?.colorScheme
    const next = themes.modes().find(mode => mode.colorScheme !== scheme)
    if (next)
      themes.setMode(next.name)
  }

  // Делегирование, а не слушатель на кнопке: кнопки могут приехать позже — из
  // острова, из перехода `ClientRouter`, из вставленного фрагмента.
  document.addEventListener('click', (event) => {
    if ((event.target as Element | null)?.closest('[data-theme-toggle]'))
      toggle()
  })
</script>
```

`setMode` ставит пару и сохраняет имя. Запись в хранилище, бросающая в приватном режиме Safari, перехвачена внутри:
режим переключится, просто не переживёт перезагрузку. Режимов больше двух — `themes.cycle()` обходит их в порядке манифеста, а
`themes.modes()` готов для меню.

`virtual:granularity/theme` несёт `themeStorageKey` и `themeCookie` интеграции, поэтому переключатель не разойдётся со
скриптом, который их читает. Типы `virtual:granum/themes` даёт granum, `virtual:granularity/theme` — этот пакет: две
строки в `src/env.d.ts`:

```ts
/// <reference types="@feugene/granum/client" />
/// <reference types="@feugene/astro-granularity/client" />
```

Рабочая версия, вместе с обработкой доступного имени, — в
[`examples/shared/src/components/ThemeToggle.astro`](../examples/shared/src/components/ThemeToggle.astro).

### Доступное имя описывает результат

«Включить тёмную тему» на светлой странице, и наоборот. `aria-pressed` здесь только запутает: непонятно, что считать
нажатым. Имя обязано обновляться при смене режима и применяться заново после того, как подмена `ClientRouter` заменит
разметку.

### Внутри Vue-острова

`useTheme()` ядра стоит на том же контроллере, ключе и паре, поэтому переключатель в острове и переключатель в разметке
Astro не расходятся. Манифест сборки ему отдаёт точка входа `@feugene/astro-granularity/app`: в браузере — один раз на
страницу, общим состоянием для всех островов (режим, переключённый в одном, доходит до остальных), с ключом
`themeStorageKey` и cookie `themeCookie`; на сервере — состоянием острова без хранилища, чтобы режим одной страницы не
утёк в другую. Своя точка входа делает то же сама — как, описано в
[руководстве ядра по режимам](https://github.com/efureev/granularity/blob/main/packages/granularity/docs/modes.md):
без манифеста ядро предполагает `slate` с `light` и `dark`.

## Клиентская навигация

`ClientRouter` снимает с `<html>` **все** атрибуты и копирует их из полученного документа:

```js
// astro/dist/transitions/swap-functions.js
const nonOverridableAstroAttributes = [...currentRoot.attributes].filter(
    ({name}) => (currentRoot.removeAttribute(name), NON_OVERRIDABLE_ASTRO_ATTRS.includes(name))
)
```

Полученный документ разбирается, а не исполняется, поэтому `data-theme` в нём нет, если пару не вписал сервер, —
инлайн-скрипт на нём не отрабатывал. Без подписки режим теряется на каждом клиентском переходе.

Скрипт закрывает это сам: granum порождает его с `reapplyOn: ['astro:after-swap']`, и шаг применения подписывается на
это событие. Он идёт тем же путём, что и при первой загрузке, поэтому пару, пришедшую с серверным HTML, не трогает. В
этой подписке важны две детали.

**На `document`, а не на `window`, и один раз.** Astro шлёт `document.dispatchEvent(new Event(name))`, а такое событие
не всплывает.

**Под `try`.** Исключение в `<head>` останавливает разбор документа, поэтому порождённый код не бросает наружу никогда —
в том числе когда `document` почему-либо отсутствует.

## Бюджет — это гейт

512 байт на теме из двух режимов; держат юнит-тест пакета и браузерный гейт. Скрипт по определению блокирует первую
отрисовку, поэтому растёт по осознанному решению, а не как побочный эффект правки. Сейчас — 407 байт на `slate` из
двух режимов и 497 с `themeCookie`.

В вашей сборке размер зависит ещё и от числа режимов: каждый приносит своё имя и свою пару. Сверх бюджета ваша сборка
получит предупреждение, а не ошибку: стоит ли режим своих байт — решать вам, а не интеграции.

## Опции

| Опция | По умолчанию | Замечание |
| --- | --- | --- |
| `themeStorageKey` | `'gr-theme'` | Где хранится имя режима. Равен `GR_THEME_STORAGE_KEY` ядра; поменяете — обязаны поменять и все, кто пишет: `useTheme`, ваш переключатель |
| `themeCookie` | — | Cookie с именем режима — для SSR с `createCookieStorage` granum. Скрипт читает её раньше `localStorage`. См. [рецепт 6](./recipes.ru.md#6-серверный-рендеринг) |
| `injectThemeScript` | `true` | Выключить, когда приложение ставит пару само и раньше |

`defaultTheme` больше нет: режим по умолчанию принадлежит теме в `granum.config`, а без сохранённого выбора скрипт
следует системной схеме. Переданная из JavaScript, опция роняет `TypeError` с этим объяснением, а не игнорируется молча.
