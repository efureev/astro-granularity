# Острова

[English](./islands.md) · **Русский**

## Оверлеям `client:only` не нужен

Ни одному компоненту ядра. Сказать это прямо стоит потому, что обычно предполагают
обратное: компонент с порталом ведь наверняка не переживёт SSR.

Переживёт. `useTeleportEnabled()` в ядре выключает телепорт на сервере **и** на первом
клиентском рендере, поэтому панели приезжают с сервера внутри разметки своего компонента
и переезжают в `body` только после монтирования. Серверная разметка и первый клиентский
рендер поэтому совпадают.

`client:only` здесь не просто лишний — он вредный: выбрасывает серверную разметку. Факт
держится гейтом, а не списком имён компонентов, потому что «работает с порталом»
выводится из устройства компонента и расходится с наблюдением.

```astro
<!-- верно -->
<OverlayDemo client:load />

<!-- выбрасывает серверную разметку -->
<OverlayDemo client:only="vue" />
```

### Что действительно надо прятать

Императивные вызовы, а не разметку. `useDialogService().confirm()`, `createLoading()` и
`setTheme()` без плагина монтируют хост в `document.body` и на сервере бросают. Их
закрывают `if (typeof window !== 'undefined')` или переносят в `onMounted`.

## Когда `client:only` — верный ответ

Когда сервер действительно не может отдать правильное, а не когда компонент «ощущается
клиентским».

```astro
<!-- «N минут назад» относительно момента просмотра. Сервер этого момента не знает
     и отрисовал бы заведомо неверное. -->
<LastChecked client:only="vue" label={t.lastChecked} locale={locale} />

<!-- Читает localStorage этого браузера. -->
<SavedPreferences client:only="vue" t={t} />
```

Отсюда два следствия, и оба кусают молча.

### Место резервирует страница, а не компонент

До монтирования компонента не существует — `min-height` внутри него не резервирует
ничего. Заглушка `<astro-island>` пуста и имеет нулевую высоту, поэтому появление острова
сдвигает всё, что под ним.

```astro
<div class="min-h-5">
  <LastChecked client:only="vue" … />
</div>
```

На странице обзора в примере это разница между CLS `0.008` и CLS `0`.

### Утилиты, использованные только там, в CSS не попадают

`granularContent(options)` покрывает `dist` библиотеки; ваши файлы подхватывает конвейер
трансформаций. Остров `client:only` отсутствует в серверной сборке, а клиентская идёт уже
после того, как таблица стилей собрана, — поэтому класс, встречающийся **только** внутри
такого острова, не генерируется никогда. Остров приезжает без оформления, без ошибки и без
предупреждения.

```ts
const content = granularContent(options)

export default defineConfig({
  content: {
    ...content,
    filesystem: [...(content.filesystem ?? []), 'src/**/*.{vue,astro,ts}'],
  },
  presets: [presetMini(), presetGranularNode(options)],
})
```

Проверять контрольными классами: уникальная утилита (`mt-[3px]`) внутри `client:only`-острова
и другая внутри `client:load`, после сборки грепнуть обе в собранной таблице. **Грепать
надо экранированную форму** — в файле лежит `mt-\[3px\]`, и шаблон без обратных косых не
найдёт ничего, создав ложную тревогу.

## Директивы гидратации

| Директива | Серверная разметка | Для чего |
| --- | --- | --- |
| `client:load` | да | Содержимое, навигация, оверлеи — всё, что обязано быть без JS |
| `client:idle` | да | Интерактивное, но не срочное |
| `client:visible` | да | Ниже сгиба. **Внимание:** остров, не попавший во вьюпорт, не гидратируется никогда |
| `client:media` | да | Зависящее от вьюпорта |
| `client:only` | **нет** | Только когда сервер не может отдать правильное |

`client:visible` заслуживает предупреждения: тест, кликающий по такому острову без
прокрутки к нему, упрётся в таймаут, ожидая обработчик, который никто не вешал.

## `provide`/`inject` между островами не работает

Каждый остров — свой корень Vue. Два острова одной страницы не могут делить
предоставленные значения.

У общего состояния три честных пути: DOM, модульный синглтон (так устроен экземпляр i18n)
или внешний стор. Для связи между островами одной страницы событие окна — самое простое,
что работает:

```ts
// пишущая сторона
window.dispatchEvent(new CustomEvent('app:preferences'))

// читающая
onMounted(() => window.addEventListener('app:preferences', refresh))
onUnmounted(() => window.removeEventListener('app:preferences', refresh))
```

Дефолты `<GrConfigProvider>` каждый островной корень ставит себе сам — app-level путь ядро
наружу не открывает.

## Авто-импорт работает только в `.vue`

Astro компилирует `.astro` своим парсером, и `unplugin-vue-components` туда не достаёт.
Импорты там явные:

```astro
---
import { GrButton } from '@feugene/granularity/components/GrButton'
---
```

## Как тестировать остров

**Дождитесь гидратации до взаимодействия.** Контрол приходит в серверной разметке и
actionable сразу, а его обработчик появляется только после монтирования Vue. Клик между
этими моментами уходит в пустоту, и тест падает по таймауту ожидания того, чего никто не
сделал.

```ts
async function hydrated(page: Page) {
  await page.waitForFunction(() => document.querySelectorAll('astro-island[ssr]').length === 0)
}
```

Атрибут `ssr` Astro снимает сам, как только остров гидратировался. Проверки **серверной
разметки** (`javaScriptEnabled: false`) звать это не должны: там гидратации не будет
вовсе.

Гонка не воспроизводится на спокойной машине — именно поэтому её стоит закрывать, а не
перезапускать прогон.

## После гидратации панели уезжают

Панель `GrSelect` в `optionsView="panel"` телепортируется в `body` после монтирования.
Тест с включённым JavaScript не найдёт её содержимое внутри разметки компонента — его там
больше нет. Ищите по всей странице или сужайте до портала.
