# Строки

[English](./i18n.md) · **Русский**

## Два рода строк, два механизма

**Строки пакетов** — подписи внутри компонентов дизайн-системы (`Поиск…`, `Очистить`,
`Закрыть`). Они приходят из `@feugene/fint-i18n`, и именно их доставляет эта интеграция.

**Строки приложения** — ваши заголовки, пункты меню, тексты. К интеграции они отношения
не имеют. Обычные объекты, разрешаемые во frontmatter `.astro` и уезжающие в острова
пропами, не стоят клиенту ничего и в снимок не попадают.

Всё ниже — про первый род.

## Конвейер

```
astro.config.mjs  →  virtual:granularity/i18n  →  точка входа ./app  →  инстанс fint
                                                        ↑
             middleware объявляет язык маршрута до рендера страницы
                                                        ↓
                 снимок отрисованных ключей кладётся в <head>
```

### Виртуальный модуль

Порождается на этапе конфига из `i18n.packages` и `i18n.locales`:

```js
import { deriveI18nBlocks } from "@feugene/astro-granularity/runtime"
import { en as en0, ru as ru0 } from "@feugene/granularity/i18n"
import { en as en1, ru as ru1 } from "@feugene/granularity-chrono/i18n"

export const loaders = [en0, ru0, en1, ru1].flat()
export const blocks = deriveI18nBlocks(loaders)
export const defaultLocale = "en"
export const locales = ["en","ru"]
export const ssrStrings = "used"
```

Именованные импорты, а не агрегат `/i18n/all`, — именно это позволяет сборщику выбросить
языки, которых вы не просили. При `locales: ['en','ru']` пакет, публикующий ещё и `es`,
отдаёт два чанка, а не три.

### Откуда берётся язык маршрута

Из `Astro.currentLocale`, прочитанного middleware **до** рендера страницы.

Другого пути нет. `@astrojs/vue` передаёт в точку входа только `app`, поэтому слой
компонентов маршрута знать не может; а `injectScript` принимает строку, фиксируемую один
раз на всю сборку. Middleware — единственный канал Astro, исполняющийся на каждую
страницу и знающий, где он находится.

Без блока `i18n` в `astro.config.mjs` `Astro.currentLocale` равен `undefined`, и
запасной путь — разбор первого сегмента пути по списку `i18n.locales`. При пустом списке
сопоставлять не с чем, и язык всегда `defaultLocale`.

### Снимок

После рендера страницы middleware вставляет перед `</head>` блок:

```html
<script type="application/json" data-granularity-i18n>
{"locale":"ru","messages":{"ru":{"gr":{"pagination":{ … }}}},"blocks":{}}
</script>
```

Точка входа острова применяет его **синхронно до `app.mount`** — это возможно потому, что
`@astrojs/vue` ожидает точку входа с обеих сторон. Первый клиентский рендер поэтому уже
совпадает с серверным, и вспышки нет.

Три решения внутри этого блока не косметические:

- **`type="application/json"`, а не инлайн-скрипт.** Браузер его не исполняет, поэтому
  `script-src` его не касается. Настоящий инлайн-скрипт, вставленный из middleware,
  захэшировать нечем — страница на этот момент уже отрисована, — и при `security.csp` он
  был бы заблокирован.
- **Перед `</head>`, а не после `<head>`.** Снимок в килобайт, вставленный сверху,
  вытолкнул бы `<meta charset>` за первые 1024 байта, и кодировку начнут угадывать.
- **Экранируется каждый `<`**, а не только `</script`. Внутри raw-text элемента `<!--` —
  второй способ выйти.

## Режимы снимка

```ts
granularity({ i18n: { ssrStrings: 'used' } })
```

| Режим | В HTML | Клиент |
| --- | --- | --- |
| `'used'` *(по умолчанию)* | Только ключи, отрисованные **на этой странице** | Догружает словарь фоном |
| `'full'` | Весь словарь языка страницы | Не догружает вовсе |
| `false` | Ничего | Как будто механики нет |

Обе величины — на страницу, а не на сайт. Ось — «только отрисованное» против «весь
словарь», и обе кладутся в каждую страницу отдельно.

Замерено на странице обзора в примере:

| | raw | gzip |
| --- | --- | --- |
| Сама страница | 10 800 Б | 3 064 Б |
| `'used'` добавляет | **+366 Б** (+3.4 %) | **+132 Б** (+4.3 %) |
| `'full'` добавляет | +11 909 Б (+112 %) | +3 945 Б (+133 %) |

`'used'` держит словарь общим кэшируемым чанком. `'full'` помечает блок загруженным,
поэтому чанк не грузится вовсе — но копия словаря теперь лежит в каждой странице, на
критическом пути документа. Для многостраничного сайта это проигрыш дважды; для
одиночного лендинга — выигрыш.

### Почему `'used'` не может сделать хуже

В режиме `'used'` `blocks` остаётся пустым, ничего не помечается загруженным, и клиент
всё равно догружает словарь фоном. Всё, что журнал не поймал, там же и долечивается. Это
улучшение по возможности, которое не может стать хуже, чем `false`.

### Чего `'used'` не видит

Строки, прочитанные через `tm()` — поддерево как данные: пункты меню, колонки таблиц.
Хук `onTranslate` для них не эмитится, поэтому в снимке их нет и они доезжают фоновой
догрузкой. У `'full'` этой дыры нет: он берёт блок целиком.

## Где механика выключает себя сама

| Условие | Почему |
| --- | --- |
| `output: 'server'` | Запросы идут параллельно в одном процессе; состояние страницы — модульная переменная, поэтому язык одного запроса мог бы попасть в ответ другого |
| `build.concurrency > 1` | Та же гонка, но на сборке |
| `i18n: false` | Модуль лоадеров не порождается вовсе |

Первые два выводят предупреждение с готовой починкой. `ssrStrings: false` объявляет
решение принятым и убирает его.

## Клиентская навигация

`ClientRouter` подменяет `<head>` целиком, поэтому снимок новой страницы в DOM есть — но
модули не переисполняются. Прочитанный один раз на уровне модуля снимок оставил бы живые
компоненты рисовать на языке первой открытой страницы, тогда как `<html lang>` и сам
снимок говорят обратное.

Поэтому точка входа перечитывает его на каждом создании инстанса, а инстансы ключуются
локалью.

**Проверяя это самостоятельно, ходите через роутер.** Присваивание
`window.location.href` — жёсткая навигация: документ свежий, поэтому ни этот дефект, ни
дефект темы не воспроизводятся, и тест поверх этого не меряет ничего.

## Экземпляры

Один экземпляр **на язык страницы**, а не на остров. Острова — независимые корни Vue, но
граф модулей у них общий, поэтому в браузере он всегда ровно один.

На сборке различие существенно: пререндер — один процесс на весь билд, поэтому
единственный модульный экземпляр зафиксировал бы язык первой отрендеренной страницы для
всех остальных. Ключевание локалью это и предотвращает.

## Шов для своего рантайма

При `i18n: false` middleware не регистрируется и снимок не порождается. Кирпичи при этом
экспортируются из `./runtime` — для приложения, которое хочет собрать тот же конвейер
поверх другого рантайма:

| Экспорт | Назначение |
| --- | --- |
| `readServerPageLocale()` | Язык маршрута, объявленный на сборке |
| `readSnapshotFromDocument()` | Снимок из разметки |
| `registerSnapshotBuilder(fn)` | Зарегистрировать того, кто его строит |
| `SNAPSHOT_ATTR` | Атрибут, который искать |

Импортируйте из `./runtime`, но не из корня: корневой вход исполняется в процессе конфига
Astro, а не в бандле пререндера, и его копия состояния всегда пуста.

Про сторону адаптера — [рецепт 4](./recipes.ru.md#4-свой-i18n-рантайм).
