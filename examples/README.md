# Стенды: одно приложение, три режима вывода

Здесь одно и то же приложение собрано тремя способами, которыми Astro умеет
отдавать сайт. Не три примера — один, показанный трижды.

```
examples/
  shared/   весь UI: лейауты, компоненты, стили, данные, строки, контент
  static/   output: 'static'                       — всё собирается заранее
  ssr/      output: 'server'  + адаптер            — всё рендерится на запрос
  hybrid/   output: 'static'  + адаптер + prerender:false на части маршрутов
```

Стенду принадлежат только три вещи: `astro.config.mjs`, `granum.config.mjs` и
тонкие обёртки маршрутов в `src/pages`. Всё, что видно глазами, лежит в
`shared/` и импортируется по алиасу `@shared`.

**Это не экономия, а метод.** Раз UI общий, расхождение между стендами не может
быть разницей приложений — остаётся ровно одна причина, режим вывода. Поэтому
`e2e/parity.spec.ts` сверяет все три и разметкой, и пиксель в пиксель, а
`e2e/dev.spec.ts` — dev-режим против собранного `dist/`.

Гейт окупился сразу: при переезде общего UI в соседний каталог `appSources`
перестал его видеть, и в CSS недосчитались 89 классов из 613. Разметка при этом
совпадала — поймала именно пиксельная сверка.

## Что меняет режим

| | static | ssr | hybrid |
|---|---|---|---|
| Когда строится страница | на сборке | на запрос | смешанно: списки заранее, карточки инцидентов на запрос |
| `getStaticPaths()` | работает | **игнорируется**, маршрут ищет запись сам | работает на пререндеренных маршрутах |
| Отчёт granum | `dist/granum-report.json` | `dist/server/granum-report.json` | `dist/server/granum-report.json` |
| Снимок строк в `<head>` | есть | **нет** | есть |
| Строки ядра на `/ru/` в серверной разметке | русские | **английские**, правятся гидратацией | русские |
| Картинки | оптимизированы на сборке, готовый `.webp` | на запрос, `/_image?href=…` | на запрос |
| 404 | файл, статус отдаёт сервер статики | настоящий ответ со статусом | настоящий ответ со статусом |

Две строки с выделением — следствие одного решения, и оно объявлено. При
`output: 'server'` интеграция не регистрирует middleware снимка строк: состояние
страницы в нём модульное, а запросы под адаптером идут параллельно в одном
процессе — язык одного попал бы в ответ другого. Вместе со снимком уходит и
объявление локали, поэтому строки **ядра** на сервере приезжают на языке по
умолчанию; строки приложения остаются правильными, их язык берётся из маршрута.
Интеграция говорит об этом предупреждением на сборке, а не молчит.

У гибрида ничего этого нет: его маршруты обрабатываются по одному.

## Запуск

Зависимостей у стендов своих нет — они резолвят пакет симлинком `link:../..`, а
`astro`, `vue` и остальное берут из `node_modules` корня. Ставить что-либо
**внутри** стенда нельзя: раскладка сломается, в дереве появится второй Vue.

```bash
# из корня репозитория, после `yarn build` пакета
cd examples/static && npx astro build && node ../../e2e/serve.mjs 4331 dist
cd examples/ssr    && npx astro build && PORT=4332 node dist/server/entry.mjs
cd examples/hybrid && npx astro build && PORT=4333 node dist/server/entry.mjs
```

`astro preview` не использовать: в Astro 7 он демонизируется и отдаёт старую
сборку. У `astro dev` та же особенность — он уходит в фон, распознав окружение
агента; для гейтов это обходит `e2e/dev-server.mjs`.

Диагностика конвейера — `yarn doctor` из корня: она прогоняет
`granum doctor --strict` по конфигу каждого стенда. Конфиги у них отдельные и
разойтись могут молча.
